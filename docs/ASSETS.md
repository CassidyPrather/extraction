# Texture assets

All textures come from CC0 libraries (Poly Haven, ambientCG) or are
generated by the script itself. `scripts/fetch_assets.py` turns them into
KTX2 files under `assets/textures/`. Every source has a row in
`CREDITS.md`.

## Running it

```bash
python3 scripts/fetch_assets.py              # fetch + build everything (~7 min)
python3 scripts/fetch_assets.py terrain      # one group: terrain | materials | foliage | sky
python3 scripts/fetch_assets.py --offline    # build from assets/.cache only
python3 scripts/fetch_assets.py --force      # rebuild even if up to date
python3 scripts/fetch_assets.py --credits    # print CREDITS.md rows for the sources
python3 scripts/fetch_assets.py --format bc7 # GPU-compressed variant (see below)
```

Needs `python3`, `numpy` and `Pillow`, plus KTX-Software's `ktx` CLI for
zstd supercompression. `scripts/cloud-setup.sh` installs `ktx` from the
KTX-Software GitHub release into `/opt/ktx-software-<version>` and links it
to `/usr/local/bin/ktx`. By hand:

```bash
curl -fLO https://github.com/KhronosGroup/KTX-Software/releases/download/v4.4.2/KTX-Software-4.4.2-Linux-x86_64.tar.bz2
echo "a8781bad05f9624edbf910b7f258cd0a4ba7d3e63b49ecc0a0ab440bf6a0a245  KTX-Software-4.4.2-Linux-x86_64.tar.bz2" | sha256sum -c
sudo mkdir -p /opt/ktx-software-4.4.2
sudo tar -xjf KTX-Software-4.4.2-Linux-x86_64.tar.bz2 -C /opt/ktx-software-4.4.2 --strip-components=1
sudo ln -sfn /opt/ktx-software-4.4.2/bin/ktx /usr/local/bin/ktx
```

Without `ktx` the script still works. It writes the same KTX2 files
without supercompression, about twice the size, and prints a warning.

## How it works

1. **Manifest.** `scripts/assets_manifest.json` lists the sources (provider,
   asset id, resolution) and the recipes that use them. On the first fetch
   the script asks the Poly Haven and ambientCG APIs for the file URLs. It
   records each URL, sha256, size and author in the manifest. Later runs
   download from the recorded URLs and stop if a hash changed. Use
   `--update-hashes` to accept a deliberate upstream change.
2. **Cache.** Downloads go to `assets/.cache/<provider>/<id>/`, which is
   gitignored. ambientCG zips are read in place and never extracted.
3. **Processing.** Everything is done in numpy:
   - Maps are resized with a wrap-aware Lanczos filter, so tiles stay
     seamless. A `repeat` key tiles a source N×N inside a layer.
   - Optional grading per entry: `recolor`, `saturation`, `tint`,
     `brightness`, and ARM overrides (`roughness`, `metallic`).
   - Every mip level down to 1×1 is generated here. Albedo is averaged in
     linear light. Normals are averaged and renormalised, and the length
     lost in averaging widens roughness (Toksvig). This is specular
     anti-aliasing, which matters in VR. Foliage mips scale alpha to keep
     the coverage at the 0.5 cut-off constant, and colours are bled out
     past the leaf edges, so cards neither thin out nor get dark fringes in
     the distance.
4. **KTX2.** The script writes the container itself as RGBA8 with all
   mips: `R8G8B8A8_SRGB` for albedo, `R8G8B8A8_UNORM` for normal and ARM.
   Then `ktx deflate --zstd 18` supercompresses it, and `ktx validate`
   checks the result. Bevy reads it through its `ktx2` + `zstd_rust`
   features.
5. **Stamps.** `assets/.cache/build_stamps.json` stores a hash of each
   output's recipe, its source hashes, the script's own hash and the
   output format. Re-running with nothing changed does nothing. Changing
   one recipe rebuilds only that output.

## Outputs

| Path | Contents |
| --- | --- |
| `terrain/{albedo,normal,arm}.ktx2` | 2D **arrays**, 7 layers, 1024², 11 mips. Layers: 0 grass, 1 forest floor, 2 mud, 3 rock, 4 gravel, 5 asphalt, 6 dirt road (fixed by `assets/shaders/terrain.wgsl`). Sampled with world-space UVs every 3 m (rock about 5 m). |
| `materials/<name>/{albedo,normal,arm}.ktx2` | Single 2D sets, 1024², 11 mips, tiling. |
| `foliage/<name>/{albedo,normal,arm}.ktx2`, `albedo.png` | Alpha cards: RGBA albedo with alpha in A, cut-off 0.5. Not tiling. The PNG is level 0, for authoring in Blender. |
| `sky/overcast_soil_2k.hdr` | Overcast HDRI for later IBL work, unprocessed. |

Conventions:

- **Normal maps are OpenGL (+Y up).** Green points towards the top row of
  the image, which is the −V direction.
- **ARM** packs R = ambient occlusion, G = perceptual roughness and
  B = metallic. Terrain layers have B = 0.
- **Load flags.** Load albedo with `is_srgb = true` and normal/ARM with
  `is_srgb = false`. Bevy's KTX2 loader picks sRGB or UNORM from that
  setting, and the default is `true`. Use a repeat sampler for everything
  except foliage.
- `bark_*` textures run with the trunk axis along V, so the birch
  lenticels are horizontal.

Materials: `bark_spruce`, `bark_birch`, `bark_pine`, `weathered_planks`,
`log_wall`, `red_brick`, `concrete_wet`, `rusty_metal`,
`painted_metal_peeling`, `corrugated_iron`, `roof_tiles_or_shingles`,
`wood_floor_old`, `plaster_wall_dirty`, `gun_metal`, `gun_wood`,
`polymer_plum`, `robot_shell`, `fabric_canvas`. Foliage: `spruce_branch`
(an atlas of fir sprigs, plus bark strips on the left and a stem along the
bottom), `birch_leaves` (one drooping twig cluster), `fern` (an atlas of
five fronds). The manifest notes each source.

Generated, not scanned:

- `bark_birch` and `robot_shell` are procedural.
- `birch_leaves` is composited from ambientCG leaf scans on procedural
  twigs.
- `gun_metal`, `polymer_plum` and `fabric_canvas` are recoloured scans.

## Sizes and the BC7 option

The default RGBA8 + zstd output is about 187 MB:

| Group | Size |
| --- | --- |
| Terrain | 54 MB |
| Materials | 116 MB |
| Foliage | 10 MB |
| HDRI | 6.5 MB |

The download cache is about 385 MB.

Raising the zstd level saves less than 1%. GPU memory use is the
uncompressed size, about 39 MB per terrain array.

`--format bc7` encodes UASTC from the same mip chain, then transcodes it to
BC7 + zstd. The files are about 2.8× smaller on disk, and GPU memory drops
4×. BC7 works on desktop and PC-VR GPUs, but standalone Quest has no BC
support. The build is slower, about 9 s per texture.

The RGBA8 output is the default and is the one tested in the game. The BC7
output has not been confirmed to work. Under the headless software renderer
(lavapipe), the BC7 terrain arrays rendered no frame within the 15-minute
`shot.sh` timeout, and no error was logged. Check it on a real GPU before
switching to it.

## Known issues

- **The terrain shader flips normal-map green.** `assets/shaders/terrain.wgsl`
  builds its tangent frame as `T = +X`, `B = cross(T, N) = +Z`. UV v runs
  along +Z, so the shader reads green as +v, which points down the image.
  That is the DirectX convention, and these maps are OpenGL. A test render
  confirmed it: a uniform "green up" normal map came out darker, not
  brighter, under the game's sun. The fix belongs in the shader: use
  `b = cross(n_geo, t)` or negate `tn.y`.
- **One upstream map is gamma-encoded.** Poly Haven `rocks_ground_09`
  ships its normal map sRGB-encoded, so flat reads 0.735 instead of 0.5.
  The loader detects this and decodes it, and logs a line when it does.

## Changing a texture

1. Edit the entry in `scripts/assets_manifest.json`. For a new source, add
   it under `sources` with only `provider`, `id` and `res`. The script
   fills in the rest.
2. Run the script and check the result in-game, for example
   `./scripts/shot.sh target/shots/x.png -30,24,200,270,-5 15`.
3. Add the `CREDITS.md` row. `--credits` prints rows for all sources.

# Models

The guns, their magazines, the robots, the truck and the small kit
(gadgets, supplies, salvage, artifacts) are modelled by Blender Python
scripts in `art/`. Nobody edits a `.blend` file: the scripts are the
source, and the exported `.glb` files under `assets/models/` are committed
next to them. Nothing external goes into them, so they need no credits.

```bash
python3 art/build.py              # rebuild every model (~30 s)
python3 art/build.py ak74 drone   # only scripts whose name matches
blender -b --python art/preview.py -- assets/models/guns/ak74.glb /tmp/ak.png   # Cycles preview
scripts/shot.sh target/shots/ak.png 40,19.2,262,0,0 20 --gallery ak74   # in the game
```

`build.py` runs each script in a fresh headless Blender (`blender` on
PATH, or `BLENDER=/path/to/blender`; written against Blender 5.2). The
`--gallery SUBJECT[,YAW[,DIST[,SHIFT]]]` option puts a gun (with its
magazine seated), any other item by id, `guns`, `drone`, `walker`,
`dirigible`, `grappler` or `pod` in front of the `--camera`, held still.
`scopeview:pso_scope,SIDE,RELIEF` holds a scope to the eye, SIDE mm off
its axis and RELIEF mm behind the eyepiece (the eye box). `sights:ak74`
brings a gun's iron sights to the eye, with the front post soft
(`--no-post-blur` for sharp). Give these 60 frames so the world loads.
At the camera above, the ground is at y = 17.6. The truck is parked at the
south gate: truck space (x, y, z) is world (40 - x, 23.7 + y, 300 - z),
standing level on a slope.

```bash
scripts/shot.sh target/shots/truck.png 44.5,25.3,292.5,-147,-4 16   # rear three-quarter
scripts/shot.sh target/shots/cab.png 37,26.8,306.8,45,-12 16        # front three-quarter
scripts/shot.sh target/shots/bed.png 39.7,26.6,298.9,177,-17 16     # in the bed
```

## Conventions

- **Game space.** `art/common.py` builds everything in game coordinates
  (metres, +X right, +Y up, -Z forward) and converts to Blender's Z-up
  only when it makes the object, so the exporter's Y-up conversion lands
  it back where it started. The numbers in a gun script read the same as
  `src/weapons/layout.rs`, and a robot script's read the same as the spawn
  code in `src/robots/`.
- **Baked ambient occlusion.** Every world model (`art/props`) carries
  its occlusion in a colour attribute, exported as COLOR_0, which the
  game's StandardMaterial multiplies into the base colour: no shader of
  its own. `common.bake_ao` ray-casts the scene (and a floor, for
  anything standing on one) from each face corner; `export(colors=True)`
  writes it. `art/check.py` fails a world model without it. Buildings'
  own boxes are shaded the same way in the game (`src/world/ao.rs`).
  `EXTRACTION_NO_AO=1` turns the buildings' shading off, for comparisons.
- **One object per motion.** A gun's top-level objects are named for the
  layout's `Moves`: `static*`, `bolt*` (slides with the bolt), `turnbolt*`
  (turns about its origin's Z axis, then slides), `barrels*` (tips about
  the layout's hinge), `trigger*`, `selector*` (turns about X), `bipod*` (turns about its origin's X to
deploy). Each
  object's origin is the point it moves from. The Mosin's bolt is coaxial
  with the bore, so its origin is on the bore axis.
- **Named points.** Empties named `pt_*` mark the layout's points for
  reference. The empty `magwell` is where the model really seats a
  magazine. The layout's seat stays the gameplay one, and the drawn
  magazine is moved from it to the model's (`seat_mag_visuals`). The
  PM's layout seat is 5 cm low and raked the wrong way, so this matters.
- **Robot parts.** A robot model has one object per part kind (`core`,
  `sensor`, `gun`/`turret`, `rotor`, `blades`, `leg_upper`, `leg_lower`;
  the dirigible's `cell_0..2` for its gas cells, and a `prop` the game
  copies onto both engines and spins).
  Each object's origin is that part's spawn offset, so it hangs straight on
  the part entity. The drone has one `rotor`, built at rotor 0. The game
  turns copies of it to face out at the other corners. Leg segments run
  along +Y from the near joint (0.8 m and 0.95 m). Their hinge axis is X,
  and `pose_leg_visuals` points it along the leg plane's normal.
- **The truck stands on its wheels** (`raid::truck::parked`), pitched up
  to 12 degrees and rolled to the ground under them. On a steeper stop,
  the low wheels hang down to the ground on their springs, up to 0.4 m
  (`wheel_droop`, drawn by `render::props::droop_wheels`). The rear ladder
  is its own node, `ladder`, hinged at the bed's tail
  (`LADDER_HINGE`), and it hangs plumb, colliders and all (`ladder_swing`).
  Pitched with the truck, its steps' faces leaned over a body pressing on
  them, and a body can't step up under an overhang. Where the ground falls
  away behind it, a cleated plank ramp hangs from the lowest tread down to
  the ground (`ladder_steps`). It used to be lowered up to 0.8 m so its
  steps reached the ground, which sank its wheels (the 28 October
  playtest, 0:12:57). `capture::footing` and
  `the_trucks_steps_reach_the_ground_at_every_stop` hold both.
- **The truck** is built round its gameplay boxes (`TRUCK_PARTS` in
  `src/raid/truck.rs`), which stay as they are: the bed floor's top is
  `FLOOR`, the canvas walls sit just outside the side colliders, the
  front board's inner face is behind the memorial board, and the rear
  ladder's treads are the step boxes' tops. Its objects are static except
  `wheel`, one road wheel built at the front right station; the game puts
  a copy at each of `WHEELS` and turns the left ones round.
- **Gloves.** `glove_{left,right}.glb` are built in the frame
  `spawn_hand` (`src/render/props.rs`) builds its joints in: palm down,
  fingers along -Z, the back +Y, the thumb on the left hand's +X. `palm`
  is the hand, thenar, knuckle guard, seams and cuff; `finger_F_J` (F 0..3
  index to little, 4 the thumb, J 0 at the knuckle) is one segment, origin
  on its joint, bone along -Z, curling about X toward -Y, parented in a
  chain at its rest pose. The game hangs each segment's mesh on its own
  joint, so the joints must agree (`every_glove_segment_is_modelled_at_its_joint`);
  segments are tapered capsules centred on the joints, so a curled finger
  stays whole over the knuckle. The index tip is `interact::poke::FINGERTIP`
  (`pointing_index_ends_on_the_poke_fingertip`). `Glove`, `Leather` and
  `Padding` are per-glove copies, tinted while the hand is in reach of
  something. `--gallery fp:open|point|<item id>` shows them first-person.
- **Worn kit.** `rig.glb` lays the rig out as worn, in torso space
  (`interact::body`: origin mid-chest under the neck): `harness_panel`
  (chest panel, shoulder straps) and `harness` (belt, the straps down to
  it) hang on the torso, and `holster`,
  `pouch`, `pocket`, `mount` and their `<kind>_flap_closed` sit at one
  slot of their kind; the game hangs each slot piece's mesh on every slot
  of its kind (`render::kit`), so the mesh is in slot space and the node's
  place is only for the art checks. `rig_open.glb` has the open flaps,
  shown while a slot holds something. The pack's `pack_lid_closed` /
  `pack_lid_open` follow `Backpack::open`. Slot positions, seats and snap
  radii are gameplay and the models are built round them. `--gallery kit`
  fills the slots (`kit+pack` also opens the pack). Worn armour
  (`weapons::armour::Worn`) draws `kit/vest.glb` (torso space) in place
  of `harness_panel`, its `plate_front` / `plate_back` while a plate is in
  that pocket, and `kit/helmet.glb` on the head (your own only in the
  sun's shadow layer: its brim would hang in your view);
  `--gallery kit+armour` puts them all on.
- **Items.** `models/items/<item id>.glb` (magazines stay in
  `models/mags/`) is in item space: origin at the centre of the item's
  `dims` box from `items.ron` (a cube of side cbrt(bulk / 1000) without
  dims), -Z forward. Models keep their sockets meaningful: lights and the
  laser have an open cell bay where a power cell seats (z 0.02), the side
  rail's top is where rail things clamp, the adapter's cradle holds an
  artifact at y 0.03, the scope's optical axis is y = 0 (its eye point is
  behind it), and the compass and map case leave room for the face,
  needle and map sheet that `src/gadgets/visuals.rs` draws.
- **Materials by name.** The model's materials are only placeholders. The
  game swaps them by name (`src/models.rs`) for the `MaterialLibrary`
  sets: `Blued` uses `gun_metal`, `Wood` uses `gun_wood`, `Polymer` uses
  `polymer_plum`, and `Shell` uses `robot_shell`. `Steel`, `Bakelite` and
  `Black` keep a scan's relief under a flat colour. `Dark`, `Eye` (the
  emissive accents, dimmed when the part dies) and `Rotor` are the robot
  palette. The truck and the kit use `Paint` (olive over the peeling-paint
  scan), `Canvas`, `Planks`, `Iron` (dark metal), `Glass`, `Rubber`,
  `Lens`, `Clear`, `Copper`, `Olive`, `Cream`, `Paper`, `Rope`, `Red`,
  `Yellow` (a true yellow), `Orange`, `Blue`, `Leaf` (green), `Enamel`
  (white enamel and white paint), `Worn` (bare steel where bluing or
  paint has rubbed off), the gloves' `Glove`, `Leather` and `Padding`, `Pebble`, `Char`, and the emissive `Lamp`,
  `LampRed`, `Glow`, `Warn`, `Ember` and `Strange`. `MATERIAL_NAMES` in
  `src/models.rs` lists them; tests check every exported model uses only
  those names (anything else renders grey) and that `art/common.py`'s
  palette lists the same. On robots `Glow` is a brighter cyan (it has to
  carry through fog) and, like `Eye`, goes dark when its part dies.
- **Rounds in magazines.** A magazine model's `round_N` objects are the
  rounds you can see (the top ones in the lips, all five in a clip);
  `show_mag_rounds` shows round N only while the magazine holds N or
  more.
- **Items fit their box.** An item model sits on the floor of its `dims`
  box and doesn't stick out of it; anything flat or long has `dims`
  rather than a bulk cube (`every_item_model_fits_its_box` checks).
  `_kit.centred` moves a model's bounds onto the box.
  Its lowest point sits within 6 mm of the box's floor: a tip poking
  below it fails as surely as one sticking out.
- **Budgets.** Guns 15-25k tris, magazines up to about 9k, items about 3k.
  Spend it where a player's face and hands are.
- **Item LODs.** An item's `<name>_lod1` node draws only beyond
  `ITEM_LOD` (6 m), its other nodes only inside it
  (`models::item_lod_range`). `check.py` doesn't count a node and its
  `_lodN` stand-ins as z-fighting.
- **Stamped text.** `text()`/`text_round()` heights are literal floats
  (the legibility test reads argument 3 from the script), and a script
  with letters is listed in `legibility::ART`.
- **Sling points.** Long guns carry `pt_sling_front` and `pt_sling_rear`
  empties at their swivels or slots.
- **UVs in metres.** Faces are box-projected, 1 UV unit = 1 m, with U
  along the gun on sides and tops, so the tiling scans keep one texel
  density and the wood grain follows the stock.
- **Fallbacks.** No file, or a failed load, gives the old blockout
  (guns, truck, gloves), placeholder box (magazines and other items) or primitive
  shapes (robots, cargo pod, harpoon launcher). The
  headless sim never loads models: it all happens in `ClientPlugin`.

## The kit

`art/common.py` has a `Part`, which is one exported object, built from:

- `prism`: a profile extruded along an axis. Its outline edges are
  rounded by `bevel` (a "rounded slab", built directly, because Blender's
  bevel clamps to nothing on finely filleted outlines). A convex corner
  rounded tighter than the bevel folds the side over itself (it z-fights
  and spoils boolean cuts near it): `report` warns, `build.py` fails the
  model, and `FOLD_DETAIL=1` lists the corners. A `width(a, b)`
  function can thicken it per point, for stocks and grips.
- `lathe`, `cyl`, `tube`: revolved profiles about the bore. They take a
  partial `sweep` for panels.
- `sweep`: a section along a path, for trigger guards and loops.
- `box` and `sphere`.
- `stock`: furniture lofted from a side outline, each cut across it a
  superellipse filling the outline's height (`width` gives the half
  widths at belly and top, `power` how square), for stocks, forends and
  grips that are round, not slab-sided.
- `cut`: an exact boolean, applied when the object is made. It drops
  cuts much shallower than half a millimetre, so engrave 0.6 mm deep.
  Lettering: `text` from `art/items/_kit.py` into a cutter Part.

The 2D helpers are `fillet` (round a polygon's corners), `catmull` and
`arc`. `make` applies the cuts, UVs, sharp edges and weighted normals,
and with `worn={...}` edge wear first (`wear`: the narrow faces of
bevels on `Blued`, or the materials you name, go to `Worn` in noisy
patches).
`join` merges Parts into one object. Keep cuts on their own Part and
join afterwards: the exact solver drops open pieces, such as a swept
trigger guard, from the mesh it cuts.

## Car wrecks

`art/vehicles/wrecks.py` (the Lada, and the helpers), `wreck_uaz.py` and
`wreck_lorry.py` write `assets/models/props/wreck_{lada,uaz,lorry}.glb`.
They use car space: metres, +Y up from the ground, -Z the front, +X the
right-hand side, and the origin on the ground under the middle of the
wheelbase.

Every part is a top-level node, and its origin is its pivot:
- doors (`door_fl`, `door_fr`, `door_rl`, `door_rr`) sit on the front
  hinge line and swing about Y;
- the `bonnet` sits on its rear hinge and lifts about X;
- the Lada's `boot` sits on its front hinge;
- the UAZ's `tailgate` and the lorry's `tailboard` sit on their bottom
  hinges and drop about X;
- `wheel_*` sit on the hub. On the lorry, the twin rear wheels are one
  node a side.

A prefab draws only `body` (`wreck_lada#body`). Destruction draws each
part as `wreck_lada#door_fl` and so on.

Yields:
- doors → `car_door`;
- `bonnet`, `boot`, `tailgate` and `tailboard` → `car_bonnet`;
- wheels → `car_wheel`.

## Model correctness

The 28 October playtest's classes M3 (seams, gaps, parts through parts,
things floating or sunk) and M4 (props at the wrong scale) are held by
lints in `src/capture/`. Each runs over every model, or every placed one
in every valley and the yard, as a `cargo test`:

```bash
cargo test --profile fast --lib capture:: -- --nocapture   # all of them, with their tallies
```

| Lint | Test | What it holds |
| - | - | - |
| Footing (`footing.rs`) | `placed_props_stand_on_what_is_under_them` | Every model a valley places (buildings' furniture and fittings, clutter, yards, staged scenes, the camp) as the game places it. Its feet (the clusters of vertices within 6 mm of its lowest point) against the nearest surface under them: the terrain, a drawn box's top, another model. A foot floats past 15 mm; a wide one sinks past 40 mm into the ground or 12 mm into a floor; a leg or post past 0.5 m. Wall fittings (windows, doors, hooks, boards) are left to the attach lint. The truck's six wheels at every stop, hanging on their springs (`raid::truck::wheel_droop`). |
| Seated (`seated.rs`) | `magazines_sit_in_their_guns`, `mounted_things_sit_in_their_mounts` | Every magazine in every gun it fits, where the model's `magwell` puts it; every item's own sockets (cell bays, the deck's tape well and cell, rails, cradles, the muzzle) with every item that fits, from a headless game. Nothing through anything deeper than 1.5 mm (generalised winding number), no faces fighting between the two, and an insert (a cell, a tape) inside its holder's outline. |
| Attach (`attach.rs`) | `model_pieces_touch_what_holds_them`, `buildings_have_no_cracks_and_doors_hang_in_their_jambs`, `rig_flaps_lie_against_their_pieces` | Every model's connected pieces touch (within 2 mm, or crossing) a chain of pieces back to its floor; no two boxes of a building face each other across a 2 to 40 mm crack (a gable's underside counts); every door's hinge is in a jamb and its leaf reaches the other; the rig's flaps touch their slot pieces and an open one doesn't stand out in front. |
| Sills (`world/clutter.rs`) | `sill_things_stand_on_their_sills`, `sills_clear_the_rooms_things` | Every house's windows' sills as its walls build them (`buildings::Geo::sills`; a shell window's board reaches `SILL_IN` into the room). Everything clutter puts on a sill, in every house of every valley and every resident in every kind of house: its feet on the ledge between the frame and the board's edge, nothing of it in the frame or through the glass, nothing in the wall beside the window. The board's room side meets no furniture or clutter (triangle against box). The footing lint's "a foot touches if any point does" let a thing hang half off a sill; this holds the whole footprint. |
| Scale (`scale.rs`) | `items_are_drawn_near_their_real_size` | Every item's real size (`REAL`: its largest side, with what it is), and the drawn model held to its rule: `Fit` (a round, a magazine, a cassette) 0.9 to 1.12 times; `Hand` (held and looked at) 0.9 to 1.4, or 1.1 to 1.6 under 15 cm, since small things read smaller in a headset; `Made` (the Zone's machines and artifacts) 0.6 to 1.7. Cooking's dishes are set aside with the cooking table. |

Small items drawn bigger than they were modelled are in `art/items/_kit.py`'s
`SCALE` (centred and scaled at export); `python3 art/items/dims.py --write`
puts their new bounds in `items.ron` as their `dims`.

Each lint's test has a `KNOWN` list: what it found that isn't fixed yet,
by model, prefab or placement. Anything new fails, and the test prints
the lines nothing matches any more (`fixed, out of KNOWN`): take those
out. On 30 October, after the second round, the lists held:
- no cracks in any prefab (closed in the third round: the cornice under
  the eaves, the shop's foot, the sawmill's purlins, the towers' landings,
  the ruins' partitions and rafters, the boxcar);
- gaps of 2 to 3 mm between pieces in about 90 models;
- a few clutter and scene things;
- the scopes bedding 2 to 3 mm onto the receivers;
- the PPSh drum, 4 mm into its well.
