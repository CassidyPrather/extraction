# The playtest tour: one new or changed thing at a time, no travel
# (`capture::station`, docs/PLAYTEST.md "The playtest tour"). Played from
# PLAYTEST TOUR on the camp board, or `extraction --playtest
# assets/playtest/tour.txt`. Nothing is saved.
#
# One station a line:
#
#   name | minutes | question (answered 1-5) | game arguments [| what to try]
#
# - The arguments are the game's own: --map, --hour, --weather, --spawn
#   x,y,z,yaw (where you stand; y 0 is the ground), --no-robots, --gallery
#   specs (src/dev.rs) and so on. They come after the command line's, so
#   they win.
# - On leaving a station the board asks the question, then for what
#   bugged you, out loud for the recording. "What to try", if given, is
#   on the board while you play it.
# - A station this build can't stage (a flag it doesn't know yet, an
#   item --give names that isn't in it) is skipped and noted: a station
#   for a fix still on its way can sit in the list.
# - Owners: give one staging line for your thing, tried with
#   `extraction --flat --playtest <a list with just your line>`.
# - `cargo test` reads this file (capture::station tests): a line written
#   wrong fails there.
